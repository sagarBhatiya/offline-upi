4. Entity-Relationship (ER) Diagram & Schema

Relational entity model depicting tables, primary/foreign keys, cardinality, and constraints.

erDiagram
    ACCOUNTS ||--o{ TRANSACTIONS : "initiates (sender_vpa)"
    ACCOUNTS ||--o{ TRANSACTIONS : "receives (receiver_vpa)"
    IDEMPOTENCY_CLAIMS ||--o| TRANSACTIONS : "authorizes / deduplicates (packet_hash)"

    ACCOUNTS {
        TEXT vpa PK "Virtual Payment Address (e.g., sagar@upi)"
        TEXT holder_name "Account holder name"
        REAL balance "Current balance (INR)"
        INTEGER version "Optimistic locking counter (default: 1)"
    }

    IDEMPOTENCY_CLAIMS {
        TEXT packet_hash PK "SHA-256 digest of ciphertext"
        TEXT claimed_at "ISO-8601 Timestamp"
        TEXT status "Claim status ('CLAIMED')"
    }

    TRANSACTIONS {
        INTEGER id PK "Auto-increment primary key"
        TEXT packet_hash FK "Matches idempotency_claims.packet_hash"
        TEXT sender_vpa FK "References accounts.vpa"
        TEXT receiver_vpa FK "References accounts.vpa"
        REAL amount "Transaction amount (INR)"
        TEXT status "'SETTLED' or 'REJECTED_LOW_BALANCE'"
        TEXT bridge_id "ID of bridge node that ingested"
        INTEGER hop_count "Mesh network hops traversed"
        TEXT settled_at "ISO-8601 settlement timestamp"
    }
Table Name Primary Key Foreign Keys / Indexed Key Constraints & Responsibilities
accounts vpa (TEXT) — Stores wallet/bank balances; uses version for optimistic concurrency locking.
idempotency_claims packet_hash (TEXT) — Atomic putIfAbsent barrier; rejects duplicate packets across concurrent BLE mesh relays.
transactions id (INTEGER) packet_hash, sender_vpa, receiver_vpa Audit ledger recording finalized states (SETTLED / REJECTED_LOW_BALANCE), hop counts, and bridge IDs.
